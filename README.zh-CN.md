## 为什么值得看

你给 Agent 加提示词、加工具、加规则，当下确实变好了。
一周后问题又回来，但你说不清是哪一次改动退化的。

这不是模型不行，是**没有闭环**。

改了什么、改完有没有用、哪条规则在被反复违反——这些全散在会话记录里，下次开新会话清零。

这套方法把「一次性调优」变成「可累积的系统」：每一次运行都留下判断，
每一次收尾都迫使系统正视自己哪里在变差。

## 三个引擎

### 1. 收尾三问

任何任务结束，必须回答：

| 问 | 要什么 |
|---|---|
| **写回** | 这次学到的东西沉淀到哪个权威源 |
| **进化** | 下一步最该动哪一处，带证据和验收判据 |
| **消融** | 哪个组件该删、该下沉、该合并 |

第三条最反直觉，也最关键。

**只做加法的系统必然臃肿。** 每次加规则前先问「有没有旧的该拿掉」，
这是唯一能阻止系统腐化的动作。

### 2. 第一性原理 + 对抗式审查

先回到本质：真正要解决什么、最小假设是什么、哪些只是「以前这么做」。

再切换成攻击者：边界在哪、失败模式是什么、三个月后哪里会爆。

一个负责想对，一个负责想漏。

### 3. 决策分级

不是所有事都该问人，也不是所有事都该自己拍。

按可逆性和影响面分五级，S/A 必须人定，B/C/D 自主执行并报备。
配套三条硬规则，其中一条是「执行中升档即停」——不许「既然开始了就做完」。

## 实际改了什么

| 之前 | 之后 |
|---|---|
| 优化靠感觉 | 每次改动有验收判据 |
| 同样的坑反复踩 | 坑变成规则，规则可追溯 |
| 规则只增不减 | 有进有出，能推翻也能清理 |
| 新会话从零开始 | 每一轮都在上一轮之上累加 |

一句话：**把 Agent 从「每次都重新开始」变成「越用越顺手」。**

## 适用场景

- 长期运行的个人 Agent / 助手
- 企业内部的 AI 工作流
- 任何「改提示词改到麻木」的项目

## 不适用

- 一次性脚本、单次问答
- 数据源都还没打通的阶段——没有数据，闭环只是在空转
